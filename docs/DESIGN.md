## Checking and repair

`src/contracts/` defines run, attempt, flag, ruling and strict API shapes. Shared libraries use small erasable TypeScript modules and explicit `.ts` imports. Fact offsets are half-open UTF-16 indices into the named source/rewrite text. Extraction precedence is verbatim → quote → date → number → entity, avoiding overlapping ledger entries. IDs are deterministic within extraction order. Required/ignored toggles, aliases, protected terms, reference time, source hash and checker/prompt/mask versions freeze on the run.

Numbers normalize selected decimal, magnitude, range, currency, percentage and half-fraction forms with multiplicity. Dates use `chrono-node` against a fixed reference instant and preserve precision and written zone; relative/ambiguous numeric dates require identical raw text. Entities use capitalization/acronym/mixed-case/protected-term heuristics and declared aliases. Quotes and verbatim spans are masked before B4 generation. A deterministic collision-checked namespace is derived from the seed, mask version and counter; restoration copies original slices. Missing, duplicated, unknown or malformed placeholders are hard failures before restoration.

`checkAttempt` requires required facts, refuses added number/date/entity keys unless a whole-token same-kind source occurrence exempts them, checks placeholder integrity, and refuses eight-word sample copying absent from the source. Ignoring a fact exempts presence only. Soft checks cover negation, modals, quantifiers, meaning-bearing phrases, bare `half`, length ratio and paragraph correspondence. Equal paragraph counts are compared by position; a merge/split falls back to whole-text counts and always emits `paragraph_alignment_uncertain`. Global count balance cannot prove that an operator stayed with its claim.

Claims align each sentence with its top three content-overlap sentences in the other direction, blank numbers/dates and run lexical overlap both ways. `ClaimJudge` admits another implementation; strict optional LLM replies use supports/contradicts/says_nothing. Only the provisional selected B4 attempt is eligible for live LLM judging, with at most four batches of 30 pairs. Missing/truncated coverage requires review. Overlap thresholds in source remain uncalibrated; a future local calibration artifact does not reconfigure deployed server constants.

`loop/step.ts` restores and checks one attempt. B4 retries only hard failures, at most three attempts, using repair requests written from stored hard flags. Selection orders by fewest hard failures, then fewest soft+claim flags, then earliest ordinal. Any hard flag means `failed`; advisory/claim/coverage flags mean at best `needs_review`; otherwise `pass`. Operational errors cannot create a passing output. Style features and mean absolute z-distance are descriptive, skip zero-variance features and disable distance below 600 sample words.

## Persistence and human control

Offline Demo uses `localStore`, bundled source/voice pairings and authored outputs. The UI imports no live client until explicit setup exploration; blocked/corrupt browser storage produces errors. Live `supabaseStore` lazily signs in anonymously and inserts raw owned inputs only. The server establishes the reference clock and derives the canonical ledger/hash/namespace; the browser preview is replaced by frozen server evidence. No browser method may append live attempts or finalize live evidence.

The state machine is `open → attempting → judging → review_ready`, with judging skipped when disabled. A new run is required for new inputs. Evidence freezes at `review_ready`. Rulings bind selected attempt, stored content hash and evidence version. Approving `needs_review` requires every soft/claim/coverage ID; failed outputs require a trimmed override reason of at least 10 characters. A monotonically sequenced later rejection revokes export. Export reloads the stored selected output, hashes its exact bytes and asks the store gate again at click; already exported artifacts cannot be revoked.

Live functions verify JWT and run ownership before privileged run operations. Model phases use durable reserve → single claim → dispatch → settlement. Settled responses can replay without current provider configuration; dispatching/unknown outcomes never imply permission to send again. Unknown outcomes retain reservations. A changed provider/model/insufficient reservation fails before claim at zero cost, with SQL protecting the claim/settle race. B3's three separately accounted phases remain one attempt. SQL owns counters, grants, evidence locks and ruling gates. These transaction/security properties remain unverified until isolated and deployed checks run.

Live erasure removes owned content and rulings, detaches response caches/identity links from accounting rows, and retains pseudonymous counters so deletion does not reset caps. It does not delete the Auth identity or retract data already sent to a provider. Anonymous history depends on session retention.

## Evaluation and recorded deviations

The authored corpus has 30 main sources in three genres plus a separate injected source, tagged gold spans, agent-authored known-good paraphrases and three full voice samples. Seeds 370037/370038 split by source into 10 dev and 20 held-out sources and pair each with two voices. Ten seeded mutators record locations and reject no-ops. B0/B1 are computed without model calls; B2/B3/B4 share canonical orchestration. Failures remain in denominators. Pair-level Wilson intervals and source-cluster summaries are diagnostic; no results have been generated.

The named `factledger`, `style`, `rulings`, `callledger`, `cited` and `evalkit` folders are small local TypeScript implementations under shared names, not imported upstream packages or claims of upstream adoption. `cited/pointer.ts` adds the proposed `text:start-end` half-open UTF-16 pointer into a separately named text; this is a proposal to the shared-module owner, **not an upstream change**. `evalkit/wilson.ts` adds Wilson intervals to the local shared-name implementation.

Spec item 13 called for hash-keyed mock recordings. The initial source instead selects `ScriptedRewriter` through `MOCK_SOURCE = 'scripted'` in `providers/mock.ts`, keyed by system/source/voice/attempt/phase. Both scripted and recorded implementations throw `MockRecordingMissing` on missing/stale inputs. The generator source uses real prompt builders, canonical `recordingKey(model,messages,maxTokens)`, prompt/mask versions and retry repair paths, but has not executed; `fixtures/mock/recordings.json` is absent. Generate, inspect, switch the constant, and validate before claiming the recording mode works. Generated scripted recordings remain mock evidence.
